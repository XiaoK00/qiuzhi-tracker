# 求职投递追踪器

将包含本文件的目录记为 `<skill-dir>`。

## 核心原则

帮助用户判断：

1. 岗位当前能否投递。
2. 岗位是否值得投入时间。
3. 用户与岗位有多契合。
4. 下一步具体做什么。

分别保存硬性门槛、优先条件、岗位价值、契合指数和当前行动。企业池管理公司层信息，岗位清单管理具体机会，投递进度保护用户维护的过程数据。

## 必须使用的资源

按任务阶段读取：

- 确定规模、联网检索和判断状态前，读取 `<skill-dir>/references/research-rules.md`。
- 计算门槛、价值、分数和行动前，读取 `<skill-dir>/references/matching-rubric.md`。
- 创建或更新工作簿前，读取 `<skill-dir>/references/workbook-schema.md`。
- 新建工作簿时，复制并编辑 `<skill-dir>/assets/qiuzhi-tracker-template.xlsx`。
- 写入 Excel 前运行 `<skill-dir>/scripts/validate_tracker_data.py`。

验证命令：

```bash
python <skill-dir>/scripts/validate_tracker_data.py <tracker-data.json> \
  --min-companies <企业最低数> \
  --min-jobs <岗位最低数> \
  --as-of <YYYY-MM-DD> \
  --normalized <normalized.json>
```

根据选定档位填写最低数。仅企业池模式将 `--min-jobs` 设为 0。验证失败时先修正数据。

## 能力边界

完成完整任务需要读取用户材料、访问招聘来源并创建或编辑 `.xlsx`。缺少能力时说明受阻环节。搜索摘要只用于发现线索，Markdown 表格只用于预览。

## 工作模式

- **新建模式**：创建四张主表。
- **增量更新模式**：在旧文件副本上更新并保护人工字段。
- **旧版精简模式**：迁移重复列和多余工作表。
- **仅企业池模式**：建立企业池，岗位最低数为 0。
- **重点核验模式**：使用用户提供的企业名单核验岗位。

# 完整工作流程

## 第 1 步：读取输入

完整读取简历、作品、旧表和用户限制，提取：

- 预计毕业年月、学历和专业
- 实习、科研、项目、作品、证书和技能证据
- 目标岗位、行业和城市
- 可接受的销售、轮岗、出差、倒班、异地和调剂条件
- 明确排除的岗位、行业和地区

只在缺失信息会明显改变检索结果时询问一个简短问题。次要缺失项使用明确标注的假设。

## 第 2 步：选择任务规模

读取 `research-rules.md`，采用一档规模：

- 轻量：20–40 家企业，5–10 个深度核验岗位
- 标准：50–80 家企业，15–25 个深度核验岗位，默认使用
- 全面：100–150 家企业，30–50 个深度核验岗位
- 自定义：使用用户指定数量或名单

根据用户时间、城市数、方向数和交付期限调整。向用户说明选定档位、目标数量和原因。

## 第 3 步：判断招募届别和基准日

按预计毕业年份判断届别。分别保存招募届别、发布日期、开放日期、截止日期、最后核验日期和任务基准日。

## 第 4 步：建立真实企业池

覆盖不同规模、行业和地区。每行一家企业，保存：

1. 企业名称
2. 企业性质及规模
3. 行业
4. 主要地区
5. 适配岗位方向
6. 企业优先级
7. 核验状态
8. 招聘官网
9. 招聘线索与风险备注

风险依据聚焦招聘主体、合同、收费、敏感信息索取、职责透明度和来源冲突。

## 第 5 步：核验具体岗位

按 `research-rules.md` 打开来源并保存：

- 岗位所属企业、名称、地点、届次和项目
- 招聘状态、截止日期和岗位新鲜度
- 核心职责
- 硬性门槛和判断
- 优先条件
- 岗位价值和依据
- 契合指数和评分分项
- 当前行动
- 来源 URL、来源等级、核验日期和状态依据

岗位所属企业必须存在于企业池。活跃岗位需要可靠来源。已过期截止日期需要更新状态和行动。

## 第 6 步：分开完成五项判断

按 `matching-rubric.md` 依次处理：

1. 硬性门槛：`满足`、`待确认`、`不满足`。
2. 优先条件：记录加分条件及现有证据。
3. 岗位价值：`高`、`中`、`低`、`待确认`，附依据。
4. 契合指数：四个分项合计 100 分。
5. 当前行动：`立即投递`、`本周投递`、`继续核验`、`持续关注`、`暂不处理`。

评分分项固定为职责匹配 35、技能证据 25、优先条件 20、工作条件 20。硬性门槛单独作为投递闸门。

## 第 7 步：验证结构化数据

运行验证器并修正：

- 重复企业和岗位记录 ID
- 岗位所属企业缺失
- 非法状态、来源等级和价值等级
- 活跃岗位缺少有效来源
- 过期截止日期与活跃状态冲突
- 岗位新鲜度与核验日期不一致
- 硬性门槛与当前行动冲突
- 分项越界、缺项或合计不等于契合指数

分数阈值告警需要人工复核。交付中说明保留告警的理由。

## 第 8 步：创建或更新工作簿

保留四张主表：

1. **求职总览**
2. **企业池**
3. **岗位清单**
4. **投递进度**

在总览显示任务档位和目标范围。岗位清单按 `workbook-schema.md` 分列展示五项判断、岗位新鲜度和来源。投递进度只加入准备投递或已经投递的岗位。

## 第 9 步：安全更新旧表

1. 复制原文件，在副本上修改。
2. 按标准化企业名称去重。
3. 按企业、届别、项目、岗位和地点组成的记录 ID 匹配岗位。
4. 更新岗位状态、截止日期、新鲜度、来源、价值和评分。
5. 保留简历版本、投递日期、当前环节、联系人、复盘和用户备注。
6. 将已截止岗位设为 `暂不处理`，保留历史记录。

## 第 10 步：最终检查

检查：

- 实际数量符合选定档位或用户自定义范围
- 企业数、已核验企业数和岗位数分别统计
- 岗位所属企业可以关联到企业池
- 截止日期、岗位新鲜度和来源等级通过验证
- 硬性门槛、优先条件、岗位价值、契合指数和当前行动清晰分列
- 评分分项完整并等于总分
- 投递进度只含准备投递或已有进展的岗位
- 记录 ID 唯一
- 公式无错误，日期和计数格式正确
- 用户人工字段得到保护
- 导出的 `.xlsx` 可重新打开并读取关键区域

只有实际使用 WPS 打开测试后才声明 WPS 实机兼容。

## 最终交付

提供：

1. 可下载的 `.xlsx` 文件。
2. 任务档位和目标范围。
3. 候选企业数、已核验企业数、岗位数和当前可投岗位数。
4. 最值得处理的岗位，最多 10 项。
5. 最契合的岗位类别，最多 5 类。
6. 信息核验基准日和需复核项目。

无法核实的内容标记为待核验、待复核、待确认或未披露。
